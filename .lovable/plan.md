## ليه بسام لازال يشتغل؟

لأن عنده نسخة قديمة من `settings.json` بالمفتاح القديم `3AO0-7PZ3-U2IG-72Z9`، والمفتاح ده **مش موجود في الـ DB أصلاً**، فالسيرفر بيرجع:
```

```

**لكن الأداة القديمة ممكن تكون مبرمجة إنها:**
1. تفتح الواجهة أولاً
2. تطلب من السيرفر في الخلفية
3. لو ما لقتش رد إيجابي — تكمّل تعمل بدون تحقق (offline mode أو bug في الكود)

## الحل الوحيد الفعلي: منع الـ API Key من إصدار أي رد للمفاتيح غير الموجودة

**الفكرة:** بدل ما السيرفر يرجع `valid: false` هادئ، نضيف **blacklist للمفاتيح القديمة** — أي مفتاح اتحذف يتسجل في جدول `revoked_keys`، وأي طلب بيه يتعامل معاه كـ IP بيتبان (يُحسب كمحاولة فاشلة وينتهى بـ 403).

---

## الخطة المقترحة

### 1. جدول جديد `revoked_keys`
```sql
CREATE TABLE public.revoked_keys (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  license_key text NOT NULL UNIQUE,
  reason text,
  revoked_at timestamptz DEFAULT now()
);
```

### 2. تعديل صفحة Licenses
عند حذف أي ترخيص أو تجديد مفتاحه → نسجل المفتاح القديم تلقائياً في `revoked_keys`.

### 3. تعديل Edge Function `validate-license`
نضيف فحص على `revoked_keys` قبل ما نرد:
- لو المفتاح موجود في `revoked_keys` → نرجع **403** (مش 404) ونسجله كمحاولة فاشلة → يكمّل في Auto-Block كأنه IP مشبوه.

### 4. إضافة المفتاح القديم يدوياً
نضيف `3AO0-7PZ3-U2IG-72Z9` في جدول `revoked_keys` فوراً.

## النتيجة

```
الأداة القديمة (settings.json قديمة)
   ↓
تطلب validate-license بـ 3AO0-7PZ3-U2IG-72Z9
   ↓
السيرفر: "هذا المفتاح ملغى" → 403
   ↓
يُحسب كمحاولة فاشلة → Auto-Block للـ IP بعد 30 محاولة
   ↓
الأداة تتوقف + IP يتبان تلقائياً
```

حتى لو بسام عمل settings.json جديدة بالمفتاح القديم، السيرفر يتعامل معاه كمحاولة اختراق مش كـ "مفتاح مش موجود".
